# 安全与架构优化执行计划

## 1. 目标

本轮优化目标：

- 修复高风险安全边界问题，优先防止跨租户访问、匿名文件读取、接口盗刷。
- 收敛 Spring Boot 项目的职责边界，提升高内聚低耦合。
- 在不破坏现有前端契约的前提下，逐步减少兼容层控制器的职责塌陷。
- 按计划项逐步实施：每个计划项一个分支，分支内多个小 commit，commit message 使用简洁明了中文。

## 2. 当前约定

- 分支策略：每一个计划项一个分支。
- commit 风格：gitflow 风格前缀 + 简洁明了中文。
- 执行顺序：按计划 1 -> 7 逐项推进。
- 当前阶段：计划 1、计划 2 已完成，计划 3 待开始。

## 4. 执行规则

1. 一次只处理一个计划项。
2. 每个计划项使用独立分支。
3. 每个计划项内拆多个小 commit。
4. 不混入其他计划项的改动。
5. 每个计划项完成后先验证，再汇报结果。
6. 涉及租户、认证、文件、菜单、权限时，必须做专项回归。

## 5. 计划 1：租户上下文一致性加固

- 分支：`feature/tenant-context-hardening`
- 状态：已完成

### 目标

- 防止 `x-tenant-id` 覆盖 JWT 中的租户信息。
- 明确已认证请求与匿名请求的租户来源规则。

### 规则

- 已认证请求：
  - token 中有 tenant 时，以 token tenant 为可信来源。
  - 如果 header tenant 存在，必须与 token tenant 一致。
  - 不一致返回 `400`。
- 匿名请求：
  - 保持 `header -> domain -> default` 解析链路。

### 小 commit

- `fix: 增加租户请求头与令牌一致性校验`
- `test: 补充租户上下文冲突场景测试`

### 验证

- `./mvnw.cmd -Dtest=TenantContextFilterTest,TenantContextFilterMissingTenantTest test`

### 已完成提交

- `a0ee830 feat: 新增安全与架构优化执行计划`

## 6. 计划 2：文件下载访问链路收口

- 分支：`feature/file-access-hardening`
- 状态：已完成
- 方案：安全优先方案

### 目标

- 关闭旧 `/api/file/**` 匿名读取。
- 所有后台文件读取统一纳入认证/授权保护。

### 执行方向

- 前端补鉴权文件加载能力。
- 富文本与历史内容做兼容渲染。

- `test: 补充文件访问鉴权与预览回归测试`
