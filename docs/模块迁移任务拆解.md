# LuckyColor Spring Boot 迁移任务拆解

## 1. 目标说明

- 参考现有 NestJS 项目 `luckyColor-admin-serve`，在 `Spring Boot 3.5.13 + JDK 17` 上重写一版后端。
- 迁移顺序遵循“基础设施先行、核心链路优先、外围能力后补齐”的原则。
- 每个小任务完成后立即提交一次，分支命名遵循 Gitflow，提交说明使用简洁中文。

## 2. 模块映射

| NestJS 模块 | Spring Boot 包建议 | 说明 |
| --- | --- | --- |
| `shared` | `com.luckycolor.admin.common` | 统一响应、异常、配置、工具、常量 |
| `infra/cache` | `com.luckycolor.admin.infrastructure.cache` | Redis 与缓存封装 |
| `infra/database` | `com.luckycolor.admin.infrastructure.persistence` | MyBatis-Plus/Mapper |
| `infra/security` | `com.luckycolor.admin.infrastructure.security` | 密码、JWT、认证上下文 |
| `infra/tenancy` | `com.luckycolor.admin.infrastructure.tenant` | 租户上下文、租户拦截、隔离能力 |
| `modules/iam` | `com.luckycolor.admin.modules.iam` | 认证、权限、数据权限、安全审计 |
| `modules/system` | `com.luckycolor.admin.modules.system` | 用户、角色、菜单、部门、字典、配置、公告、日志 |
| `modules/tenant` | `com.luckycolor.admin.modules.tenant` | 租户、租户套餐、租户初始化 |
| `modules/platform` | `com.luckycolor.admin.modules.platform` | 控制台、文件、健康检查、国际化、偏好、水印、代码生成 |

## 3. Gitflow 约定

- 主分支：`main`
- 集成分支：`develop`
- 功能分支：`feature/<模块>-<任务>`
- 发布分支：`release/<版本号>`
- 热修复分支：`hotfix/<问题>`

提交信息格式建议：

```text
<模块>：<动作><结果>
```

示例：

```text
基础设施：初始化应用骨架
认证中心：完成登录接口
菜单管理：支持路由树查询
租户中心：接入租户上下文
```

## 5. 推荐实现顺序

1. 先完成 `P0`，尤其是租户上下文、安全基线和持久层。
2. 再推进 `P1` 与 `P2`，把租户、登录、权限三条主链路打通。
3. `P3` 优先顺序建议为：菜单、角色、用户、部门、字典、配置、公告、日志。
4. `P4` 属于平台能力，可以在系统主链路稳定后并行推进。
5. `P5` 放在每阶段穿插执行，但在首个可联调版本前必须补齐。
